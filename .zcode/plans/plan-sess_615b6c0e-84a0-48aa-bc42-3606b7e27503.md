# Plan: send the deploy API version (workflow file) from serf to stat

## Context
The selected-run timeline's "serf actions ↗" item links to the hardcoded https://github.com/Artanty/serf/actions. It should link to the workflow file that actually ran (https://github.com/Artanty/serf/actions/workflows/deploy_v2.yml) and show the API version. Only the serf master workflow knows which file ran, so it is the sender. Slaves are untouched.

## Changes

### 1. serf `.github/workflows/deploy_v2.yml`
- Existing step "Set working directory" (second step, before any send; no new step): add two lines to `$GITHUB_ENV`
  - `DPL_WORKFLOW_REF=${{ github.workflow_ref }}` (e.g. `Artanty/serf/.github/workflows/deploy_v2.yml@refs/heads/master`)
  - `DPL_API_VERSION=2` (hardcoded to match the `_v2` file name)
- The three master send steps (MASTER_START, MASTER_END, MASTER_ERROR): add env `DPL_WORKFLOW_REF: ${{ env.DPL_WORKFLOW_REF }}` and `DPL_API_VERSION: ${{ env.DPL_API_VERSION }}`, then in jq `--arg wfr "$DPL_WORKFLOW_REF" --arg api "$DPL_API_VERSION"` → `workflowRef:$wfr, apiVersion:$api`.
- `deploy.yml` (v1), if it still exists: same two lines with `DPL_API_VERSION=1`, same payload additions, so old-API runs are labelled too.
- Slave steps: no change (the run takes both values from any master event).

### 2. stat `back`
- `core/ensure_deploy_columns.ts`: add `workflowRef VARCHAR(255) NULL` and `apiVersion VARCHAR(16) NULL` (idempotent, added on boot).
- `app.ts`: `AddEventBody` gains `workflowRef?: string`, `apiVersion?: string`; both added to `extras`.
- `core/deployRuns.ts`: both on `DeployEventDto`; on `DeployRunDto` run-level `workflowRef`, `workflowFile` (basename of the ref, e.g. `deploy_v2.yml`) and `apiVersion` (first non-empty).

### 3. stat `web`
- `api.service.ts`: extend `DeployRun` with `workflowRef` / `workflowFile` / `apiVersion`.
- `deployTimeline.tsx`: the 'master start' item shows the API version + workflow file (e.g. `api v2 · deploy_v2.yml`; old runs without the field show `api v1`) and links to `https://github.com/<owner/repo from workflowRef>/actions/workflows/<file>`; falls back to the current hardcoded link when `workflowRef` is null. `MiniPage` shares the builder and gets it automatically.
